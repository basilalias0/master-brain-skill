# A/B 2026-11-19: rules restored from unify-v2 (536b241) against 79e3757

3 tasks × 3 cells × 3 runs = 27 runs, all at mid tier (T1), default effort. Cells: **new** (536b241), **prev** (79e3757),
**control** (same prompt, no skill). Harness adapted from the 2026-10-05 one: t5 and t8 unchanged (mutants, hidden test,
test guard), plus a new task t10. Rubrics were written and checked against a reference fix before any run.

## t10 "signup usernames allow hyphens" (the task the change targets)
Fixture: a signup form (`client/`) and server schema (`server/`). The form is looser than the server on username length,
case and password length; a missing username makes the server throw (500); the email-case difference is marked intended.
Pass = all of: H1 hyphen accepted both sides · H2 the form matches the server on username length (contract diff) ·
H3 a blank submission is a 400, not a 500 (robustness pass) · H4 the intended email exception is kept · existing tests
green · tests added · no test-guard violation.

## What it shows
1. **`flows.md` did not earn its place as written.** The pointer at the end of the tester module was followed in 1 of 3
   runs, and the run that read it still did not fix the mismatch or the 500. The rules say what a mismatch *is*; they do
   not say to fix it in the same change, and the agents (and the control) defaulted to "report, out of scope".
2. **Detection is not the gap at this tier:** the no-skill control noticed both bugs 3/3. A rule that only improves
   detection adds nothing measurable here.
3. **The skill helps on t5** (3/3 against 0/3 for control: the control misses one mutant), and costs about 3x the tokens
   on t8 for the same result as control.
4. The scripts in 536b241 (`decisions.cjs archive`, the DL nudge) are covered by unit tests and not exercised here.

## Cost

## Round 2: the rule rewritten (9598376), t10 only
The owner chose the rewrite. The tester `Contract:` line (Phase 2, always read) now says: a field the task touches that
form and server both check is diffed first, and a looser form or a 500 on blank or missing input is fixed in this change
with a test, never left out of scope. `flows.md` says the same. Four other lines were reworded to fit the cap with no
rule dropped (the "one heavy run at a time" note is law 7's heavy slot). 9 new runs: new2 ×3, prev ×3, control ×3,
same fixture and prompt; prev and control below pool rounds 1 and 2.
