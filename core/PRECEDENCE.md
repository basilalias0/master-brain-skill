# Precedence

Order of authority, highest first:

1. The human.
2. LAWS (the project's `LAWS.md`).
3. The Master's brief.
4. The project's own `CLAUDE.md` or equivalent.
5. Skill modules (research, lean, developer, analyzer, tester).

## Which skill when
- **lean:** phase 1 and bug fixes.
- **developer:** new modules (build) and changes to connected code (update).
- **analyzer:** Master runs it to fill BOARD `Touches` and a dated FEATURE_INDEX verdict.
- **tester:** the phase in the brief.
- **research:** before a LOCK, or when logs do not answer.
- Phase 2 (optimise) follows LAWS.

lean never overrides a LOCK, tests, security or the file-size laws. A lower rule never relaxes a higher one.
